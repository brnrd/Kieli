# Translation file formats

Workspace admins can choose **Admin → Import translation files** to create a new project from a single file or a ZIP of language files. Existing projects are never overwritten. Preview happens in a browser worker; no file is uploaded for preview. Review language assignments, sample keys and warnings before importing. The same retryable, permission-checked batches used for Lokalise imports save the project.

Name files `en.json`, `fr.strings`, etc. Apple paths such as `fr.lproj/Localizable.strings`, Android paths such as `values-fr/strings.xml`, and ordinary locale directories are recognized. ARB `@@locale` and XLIFF `target-language` can supply the language when the filename does not. A single file can use the **File language** override. ZIP files with multiple languages must identify each language in filenames, directories or format metadata. Multiple files for one language can contribute distinct keys; duplicate key/language pairs are rejected.

## Supported adapters

Each adapter handles keyed text; this is not a promise to preserve arbitrary files sharing an extension. The import dialog and export selector show these limits.

| Format                  | Extension / CLI `--format`   | Supported content                                                                                                                                                                                                                                                                                                                                                          |
| ----------------------- | ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| JSON                    | `.json` / `flat`, `nested`   | Flat or nested string maps; dotted/nested collisions rejected. Arrays, nulls, booleans and numbers are not coerced.                                                                                                                                                                                                                                                        |
| YAML                    | `.yml`, `.yaml` / `yaml`     | String maps, including nested maps. Aliases, anchors, explicit tags and multi-document streams are rejected.                                                                                                                                                                                                                                                               |
| JavaScript / TypeScript | `.js`, `.ts` / `js`, `ts`    | One `export default { ... }` or `module.exports = { ... }` literal string map; TS `as const` and `satisfies` wrappers are accepted. Imports, calls, getters, functions, spreads, variables, computed properties and executable statements are rejected. Uploaded code is never executed.                                                                                   |
| PHP                     | `.php` / `php`               | One `<?php return [ 'key' => 'value' ];` flat array of single-quoted string literals. No expressions or code execution.                                                                                                                                                                                                                                                    |
| Java properties         | `.properties` / `properties` | String properties, continuation lines, escaped separators and `\uXXXX` escapes. UTF-8 input; no automatic legacy-encoding guessing.                                                                                                                                                                                                                                        |
| INI                     | `.ini` / `ini`               | String pairs; sections flatten to dotted keys. Export quotes values using JSON string escapes. Other INI dialects are not implied.                                                                                                                                                                                                                                         |
| .NET RESX               | `.resx` / `resx`             | String `<data><value>` resources; typed objects, file references, binary values and per-entry comments are rejected. Standard RESX headers/schema are accepted but regenerated on export.                                                                                                                                                                                  |
| Keyed gettext           | `.po`, `.pot` / `po`, `pot`  | Key IDs in `msgid`, strings in `msgstr`, UTF-8 headers and multiline quoted values. Prose message IDs outside Keylo's key syntax, contexts, fuzzy/obsolete entries and gettext plural records are rejected. POT intentionally exports empty translations. Comments/headers are not retained.                                                                               |
| Apple strings           | `.strings` / `strings`       | Quoted string pairs, comments, Unicode escapes. UTF-8 export; BOM-marked UTF-16 input is also accepted.                                                                                                                                                                                                                                                                    |
| Apple XML plist         | `.plist` / `plist`           | String dictionaries; nested dictionaries flatten to dotted keys. Binary plists, arrays and non-string values are rejected. Export is a flat string dictionary.                                                                                                                                                                                                             |
| Android                 | `.xml` / `android`           | Plain `<string>` and cardinal `<plurals>` resources with count placeholders. Export requires lowercase Android resource IDs; keys are never renamed. Arrays, complex/nested ICU, inline markup, non-translatable resources and `formatted=false` are rejected.                                                                                                                                          |
| Flutter ARB             | `.arb` / `arb`               | String messages, including unmodified ICU message strings, plus `@@locale`. Other metadata is rejected until it can be preserved. This is not an ICU validator/compiler.                                                                                                                                                                                                   |
| XLIFF 1.2               | `.xliff`, `.xlf` / `xliff`   | Plain-text `<trans-unit id="key">` records with one source and at most one target. Each file imports its target (or source if target is absent). Include the source-language file too when importing both languages. Export includes source and target language metadata and source copy. Inline codes, groups, notes, headers and segmented/XLIFF 2.x files are rejected. |
| CSV                     | `.csv` / `csv`               | UTF-8 `key,value` columns with RFC 4180 quoting. Optional third `encoding` column preserves Keylo's formula protection. Export prefixes formula-like cells with an apostrophe and marks `encoding=apostrophe`; reimport removes only marked prefixes. Original apostrophes remain intact.                                                                                  |

Comments, layout, non-key/value headers and unrelated application resources are not retained. Where accepting an unsupported structure would discard meaningful data, parsing fails before project creation. Format-specific warnings require acknowledgement. Translations remain text throughout the editor; no uploaded markup is rendered as HTML.

Apple plural dictionaries (`.stringsdict`) and Xcode localization bundles (`.xcloc`) are not implemented. Full plural/placeholder metadata and package reconstruction need dedicated adapters. STF is also unsupported. Document, spreadsheet, subtitle and layout formats (`.doc`, `.docx`, `.xls`, `.xlsx`, `.pptx`, `.idml`, `.html`, `.srt`) are outside this implementation.

## Export, API and CLI

The project's **Export** dialog chooses a format, languages and optional source fallback. It downloads a ZIP with one `<locale>.<extension>` file per language. Missing translations remain empty unless fallback is selected. A keyed POT template always has empty `msgstr` values regardless of fallback.

```sh
KEYLO_TOKEN=... node cli/keylo.mjs pull \
  --url https://copy.example.com \
  --project website \
  --languages en,fr \
  --format strings \
  --out ./locales
```

The CLI uses Node built-ins only. It validates all filenames and the selected languages before writing, uses temporary files and atomic per-file replacement, and preserves unrelated files. A filesystem failure may leave earlier locale files updated; the pull is not an atomic directory-wide transaction. CI should stop on non-zero exit status.

`GET /api/projects/<id>/export?format=<id>&languages=en,fr&fallback=false` retains the existing `{project,format,translations}` JSON response for `flat` and `nested`. Other formats return `{project,format,files:[{name,content}]}`. Add `download=zip` to any supported format to download files directly. These remain authenticated project exports: users need read access, and bearer export credentials can only read their assigned project's export endpoint.

Imports are capped at 10 MB input, 25 MB uncompressed ZIP data, 10 MB per file, 1,000 entries, 30 languages, 50,000 keys, 20,000 characters per translation and 120 KB per saved key. Key names use Keylo's existing 180-character ASCII identifier syntax. Unknown archive formats, unsafe paths, duplicate filenames/keys, malformed XML and XML entities/DTDs are rejected. Only Apple's fixed standard plist DOCTYPE is stripped without resolving it.

Exports cap accumulated text and uncompressed file content at 10 MB and HTTP downloads at 4 MB. JSON transport escaping counts toward the response budget. Export fewer languages or split the project when a limit is exceeded. The HTTP cap leaves room for binary base64 encoding and response-envelope overhead under [AWS Lambda's synchronous payload limit](https://docs.aws.amazon.com/lambda/latest/dg/gettingstarted-limits.html); streaming/object-storage exports are not implemented.

Format references: [Apple string resources](https://developer.apple.com/go/?id=string-resources), [Android string resources](https://developer.android.com/guide/topics/resources/string-resource), [Flutter internationalization](https://docs.flutter.dev/ui/internationalization), [XLIFF 1.2](https://docs.oasis-open.org/xliff/v1.2/cs02/xliff-core.html), [GNU gettext](https://www.gnu.org/software/gettext/manual/html_node/PO-Files.html), [CSV injection protection](https://community.owasp.org/attacks/CSV_Injection).

Plural keys now retain ICU MessageFormat as one key. JSON/YAML category objects and Lokalise snapshot plurals import without flattening forms. Android cardinal `<plurals>` supports count placeholders. Other existing adapters preserve ICU strings; native gettext plurals and Apple `.stringsdict` remain unsupported. See [plurals and referencing](messages.md) for the exact contract.
